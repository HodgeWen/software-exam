# React 19.2

本文件适用于 **19.2.x**。按下面写。19.0 / 19.1 的 Actions、`use`、`ref` prop、Context 当 provider 照用，不要退回 `forwardRef` / `useFormState` / `<Context.Provider>`。

## 19.0 / 19.1 仍该用（细节按需打开旧档）

| 档 | 现在仍用 |
| --- | -------- |
| 19.0 | `useActionState`、form `action`、`useFormStatus`、`useOptimistic`、`use()`、`ref` 当 prop、`<Context value>`、ref cleanup、`prerender` |
| 19.1 | Owner Stack 仅 DEV；Suspense 边界按 19.1 行为 |

## `<Activity>`

替代「卸载就丢状态」的条件渲染。要保留输入/滚动、还可能马上回来时用它，不要 `isOpen && <Panel />`。

```tsx
import { Activity } from 'react'

<Activity mode={tab === 'a' ? 'visible' : 'hidden'}>
  <PanelA />
</Activity>
```

- `hidden`：`display: none`，**拆掉 Effects**（须有 cleanup），更新降优先级。DOM 与 React state 保留。
- `visible`：正常显示、挂 Effects。
- 隐藏期间 `<video>` / `<audio>` 不会自动停，要在 `useLayoutEffect` 里自己暂停。
- 背景预渲染只认 Suspense 数据源；`useEffect` 里 fetch 不会在 hidden 时预取。
- 只返回纯文本、没有 DOM 节点的子树，hidden 时可能什么都不输出。

不需要保状态就继续用条件渲染，不要把整页都包 Activity。

## `useEffectEvent`

把「从 Effect 里发出的事件」拆出去，让 Effect 只依赖真正该重连的值。

```tsx
import { useEffect, useEffectEvent } from 'react'

function ChatRoom({ roomId, theme }: { roomId: string; theme: string }) {
  const onConnected = useEffectEvent(() => {
    showNotification('Connected!', theme)
  })
  useEffect(() => {
    const connection = createConnection(roomId)
    connection.on('connected', onConnected)
    connection.connect()
    return () => connection.disconnect()
  }, [roomId])
}
```

硬规则：

- 只在**同一个组件/Hook 的 Effect**（或其它 Effect Event）里调用。不要传入子组件、不要在 render / 点击处理里调。
- **不要**放进依赖数组。装 `eslint-plugin-react-hooks@latest`（19.2 起 `recommended` 默认 flat config）。
- **禁止**用来删掉本该列入的依赖。`pageUrl` 变了就该重跑就留在依赖里。
- 身份每次 render 都变，这是故意的。

## `cacheSignal`（仅 RSC）

```ts
import { cache, cacheSignal } from 'react'

const dedupedFetch = cache(fetch)

async function Component() {
  await dedupedFetch(url, { signal: cacheSignal() })
}
```

`cache()` 生命周期结束（渲染完成 / 中止 / 失败）时 abort。Client 组件不要用。

## 其它 19.2

- `useId` 默认前缀改成 `_r_`（兼容 `view-transition-name` / XML 名）。不要依赖 `«r»` / `:r:`。
- Partial Pre-rendering：`prerender` 带 `AbortController` 得到 `postponed`，再用 `resume` / `resumeAndPrerender`（Web Stream）或 `resumeToPipeableStream` / `resumeAndPrerenderToNodeStream`（Node Stream）。**Node 里仍优先 Node Stream**，Web Stream 更慢且默认无压缩。
- SSR 会短暂合并 Suspense 揭示，对齐客户端；不要为此再加人工 delay。
- 没有框架 RSC 时不要自己接 `cacheSignal` / resume。
